## 할 일

### 1. 한국 계산기 (계획서 1-2(8), 설계 3-5)

- 지연손해금 일수: 변제기 다음 날부터 변제일 **당일까지 포함**(F5). 원 미만 **버림**. 1년 **365일 고정**(윤년도 365, F20은 명세대로 정리). `Decimal`만 사용.
- 일부 변제 충당 순서: 비용 → 이자·지연손해금 → 원본(민법 제479조).
- 이자 구간:
  - 대여일부터 변제기까지: 약정 이율. 약정이 없으면 이자 없음(F6). 약정 이율이 연 20%를 넘으면 경고를 남기고 20%로 계산.
  - 변제기 다음 날부터: 지연손해금. 약정 이율이 법정이율보다 높으면 약정 이율(민법 제397조), 아니면 민사 연 5%, 상사 연 6%(`transaction_kind` 사용자 선택값).
  - 송달 다음 날부터 연 12%는 금액을 미리 정하지 않고 청구취지 문구에만 넣음. 기존 송달일 기반 총액 계산은 "참고값(기준일 표시)"으로만 남깁니다.
- 출력에 남은 원금, 지연손해금 **기산일**(마지막 충당일 다음 날, 변제가 없으면 변제기 다음 날), 청구취지 이율 문구 슬롯을 포함합니다.
- 고정 테스트(그대로 일치해야 함): 원금 5,000,000원, 대여일 2026-03-10, 변제기 2026-04-10, 이자 약정 없음, 2026-05-01 1,000,000원 변제 → 기간 21일, 지연손해금 14,383원, 충당 14,383원·985,617원, 남은 원금 **4,014,383원**, 기산일 **2026-05-02**, 청구취지:
  > 채무자는 채권자에게 4,014,383원 및 이에 대하여 2026. 5. 2.부터 이 사건 지급명령 정본 송달일까지는 연 5%, 그 다음 날부터 다 갚는 날까지는 연 12%의 각 비율로 계산한 돈을 지급하라.
- 추가 테스트: 약정 연 12%(대여 기간 이자 발생, 지연손해금도 12%), 상사채권 연 6%, 약정 연 24% 입력(경고 + 20%), 변제 없음, 변제가 지연손해금보다 작은 경우, 과오납.
- 기존 테스트의 기대값은 새 규칙 때문에 바뀌는 것만 고치고, 리포트에 손 계산식을 적습니다(예: 일수 포함 규칙, 365일 고정).

### 2. 서류 문구 (F4, F6)

- 내용증명·전자소송 문구에서 "금 X원을 대여"의 X는 **처음 빌려준 원금**입니다. 일부 변제가 있으면 "그중 Y원을 받았고 남은 원금은 Z원"처럼 사실대로 씁니다.
- 청구취지는 위 고정 문구 형식을 따릅니다. 기산일과 송달일까지 이율(약정·법정)은 계산기 출력을 씁니다.

### 3. 게이트 (G2, G4, 메시지 정리)

- G2 요건 칸 결손: 이체 증빙, 변제기 근거, 당사자 이름이 없으면 `HUMAN_CHECK_REQUIRED`와 빈 칸 목록. 메시지는 양식 칸 기준 문장으로 씁니다(설계 3-7: "이 양식의 다음 칸을 채울 근거가 없습니다: …").
- 법적 판단 표현 제거(리뷰 R3): "청구권이 발생하지 않았습니다", "법적 청구 대상이 존재하지 않습니다", 400 응답의 "법적 요건사실 결손" 같은 문장을 사실 문장으로 바꿉니다. 예: "변제기(2026-06-30)가 기준일(2026-06-01)보다 뒤입니다. 확인할 칸: 변제기", "입력한 변제 합계가 원리금 이상입니다. 확인할 칸: 변제 내역", "서류를 만들 수 없습니다. 아래 칸을 확인하세요."
- G4 한도: 한국 총액 30,000,000원 초과는 차단하지 않고 안내 문장("소액사건 범위 3,000만 원을 넘습니다. 지급명령 문구는 만들 수 있습니다")을 남기고(F14), 미국 $12,500 초과는 지금처럼 차단.
- LLM 청구금액 경로(리뷰 R4): 초안 금액이 계산값과 다르면 값을 "복원"하지 않고 보류(`missing_requirements`에 "초안의 금액이 계산값과 다릅니다")로 바꿉니다. "복원", "강제" 문구를 지웁니다. 화면 호환을 위해 응답 **필드 이름은 바꾸지 않습니다**(`tampering_reconciliations` 등). 필드 설명(description)만 사실대로 고칩니다.

### 4. 초안 검사 G1a·G3와 슬롯 (`draft_gates.py`, 설계 3-6·3-7)

- 입력: `SlotDraft { lang, sentences[ { sentence_id, type: fact|user, text_with_slots, ex_refs[] } ] }`, 허용 슬롯 이름 목록, 기준값 당사자 이름 목록, 존재하는 호증 번호 목록.
- 슬롯 문법: 값 슬롯 `{{principal}}`, 인용 슬롯 `{{quote:EX1:item3}}`, 근거 태그 `[[EX:1]]`, 사용자 진술 `[[USER]]`.
- G1a 거부 대상(슬롯 밖): 아라비아 숫자, 한글 수사(예: "오백만 원", "5백만원", "삼십일"), 날짜(예: "4월 10일", "2026. 4. 10.")와 상대 날짜("다음 달", "지난주", "열흘 뒤"), 기준값 당사자 이름의 전체·성·이름만·호칭("김 씨"), 허용 목록에 없는 슬롯 이름, 정형 문구("지급하라" 등 청구취지 문구).
- G3 거부 대상: `fact` 문장에 `[[EX:n]]`이 없음, 없는 호증 번호, `user` 문장에 `[[USER]]` 없음.
- 결과: `GateResult { gate, status, findings[ { sentence_id, message, fix_hint } ] }`.
- 슬롯 치환 함수: 확인값으로 치환 후 남은 `{{...}}` 0개를 확인. 인용 슬롯은 넘겨받은 원문으로 바꿉니다.
- 테스트(계획서 4-6): 정상 초안 통과, 유형별로 고르게 섞은 변조 100건 자동 생성 → 100% 차단. **오탐 방지**: "일부를 갚았다", "이후 연락이 없다", "이 돈" 같은 평범한 한국어 문장 20개 이상이 G1a를 통과해야 합니다(조사 "이", "일부"의 "일"을 숫자로 잡지 않음).

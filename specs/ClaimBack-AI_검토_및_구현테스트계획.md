## 1. 검토 결과

### 1-1. 반드시 고칠 것

#### (1) Muse Wonder 사용 불가 (한국)
- Meta 공식 모델 문서: "Muse Wonder and Muse Wonder Full aren't currently available in South Korea, on Model API or in Muse Code." (2026-11-02 재확인)
- Meta 지역 이용 정책(2026-10-12 갱신)에서 한국은 금지 지역이 아니고, 모델별 국가 제한은 "Muse Image: India" 하나뿐입니다. 따라서 Muse Spark, Muse Image, SAM 3.1, Muse Voice Transcribe는 한국에서 쓸 수 있는 것으로 봅니다.
- 정책은 지역 제한 우회를 금지합니다. VPN으로 Wonder를 쓰면 안 됩니다. Muse Code에서도 마찬가지입니다.
- 조치: 사실 정리와 청구원인 생성을 `muse-spark-1.3`으로 바꿉니다. Spark도 컨텍스트가 1,048,576 토큰입니다.

#### (2) 법률 포지셔닝
- 변호사법 제109조 제1호는 "금품·향응 또는 그 밖의 이익"을 받거나 약속하는 것을 요건으로 합니다. 그래서 무료 도구는 이 조항에 해당하기 어렵다는 논리 자체에는 근거가 있습니다. 법률 칼럼(오정익, 2026-05)도 사용자가 쓴 내용을 양식에 기계적으로 넣어 주는 자동화 서비스는 금지 대상에 들지 않는다고 봅니다.
- 그래도 "우회", "원천 조각" 같은 단정 표현은 빼야 합니다.
  - 후원, 광고, 유료 전환, 변호사 연결 수수료가 붙는 순간 무료 논리가 무너집니다.
  - 대한변협은 리걸테크 기업과 법무법인의 AI 서비스에 대해 변호사법 제34조 제5항·제109조 위반으로 형사고발을 검토한 적이 있습니다.
  - 법무사법 제3조는 법무사가 아닌 사람이 법무사 사무를 "업으로" 하지 못하게 하고, 그 사무에는 "다른 사람이 위임한 법원 제출 서류 작성"(제2조)이 들어갑니다. 법제처는 같은 구조의 행정사법 제3조에 대해 보수를 받지 않아도 계속·반복하면 위반될 수 있다고 해석했습니다(21-0108). 법무사법에 같은 해석이 적용되는지는 확인이 필요합니다.
  - 해외 심사위원에게 "법 우회"라는 문구는 감점 요인입니다.
- 미국: "각 주 가이드라인에 완벽히 부합"은 근거 없는 단정입니다. UPL(비변호사 법률행위) 기준은 주마다 다르고, 무료라는 이유만으로 UPL에서 빠지지는 않습니다(일반론, 확인 필요).
- 조치 (설계 원칙으로 반영):
  1. 사건 평가(승소 가능성, 청구 가능 여부 판단)와 법적 조언을 하지 않습니다. 발화의 법적 성격(예: 채무 승인 여부)도 판단하지 않습니다.
  2. 서류에는 사용자가 확인·수정한 사실값만 들어갑니다.
  3. 서류는 표준 양식(지급명령 청구취지 정형문, SC-100)에 확인값을 배치하는 방식으로 만듭니다. AI는 사실 문장 초안만 쓰고, 그 초안은 게이트를 통과한 뒤 사용자가 문장별로 수정·승인합니다.
  4. 무료, 광고 없음, 변호사 연결 없음. UI와 서류에 "본인 작성용 초안, 법률 자문 아님"을 표시합니다.
  5. 공식 도움 창구를 안내합니다: 대한법률구조공단(132), 법원 전자소송 안내, 캘리포니아 Small Claims Advisor.
  6. 영문 포지셔닝 예: "A free self-help tool that organizes your own evidence and fills standard court forms with facts you confirm."
- (v2.2) 법적 위험이 가장 큰 지점은 AI가 청구원인 문장을 지어 쓰는 부분입니다(리뷰 D4). 해커톤 범위에서는 문장별 수정·승인 UI로 대응하고, 공개 배포 전에는 사건 유형별 고정 문장 틀 방식을 검토하며 변호사 검토에서 이 부분을 꼭 묻습니다.

#### (3) 금액 한도와 관할
- 원안의 대상 금액은 $1,000~$25,000인데, 캘리포니아 소액재판은 개인 $12,500, 법인 등 $6,250이 한도입니다. 개인은 $2,500 넘는 청구를 연 2건까지만 할 수 있습니다.
- 한국 소액사건은 3,000만 원 이하입니다. 지급명령은 금액 제한이 없습니다.
- 조치: 한도 게이트(G4)를 둡니다. $12,500을 넘으면 미국 트랙을 막고 초과분 포기 또는 일반 민사 절차 안내 문구를 보여 줍니다. 3,000만 원을 넘으면 소액사건 대신 지급명령을 안내합니다.
- (v2.2) 관할 법원은 판정하지 않습니다(리뷰 C3). 한국 지급명령은 채무자 주소지 등 정해진 법원에 내야 하고(민사소송법 제463조, 확인 필요), SC-100에도 법원을 고른 이유를 적는 칸이 있습니다. "채무자 주소"와 "제출 법원" 입력칸, 법원 찾기 안내 링크만 두고, 사용자가 고른 법원명을 슬롯으로 넣습니다.

#### (4) 범위 과다

### 1-2. 고치면 완성도와 점수가 오르는 것

#### (5) SAM 3.1 역할 재정의
- SAM 3.1은 짧은 명사구, 박스, 점으로 지정한 대상을 이미지와 영상에서 분할·추적하는 모델입니다. 말풍선 안 문장("다음 달까지 꼭 갚을게")을 읽고 분류하는 일은 Muse Spark가 맡습니다.
- 조치: 판독은 Spark, 분할은 SAM으로 나눕니다(Meta 문서가 권하는 조합).
  - Spark 1.3: 화면의 글자, 금액, 날짜를 읽고 대략적인 위치(박스)를 냅니다. 말풍선마다 사실 유형(빌려 달라는 요청, 금액 언급, 상환 약속과 날짜, 독촉)을 붙입니다.
  - (v2.2) Spark는 "채무 인정"처럼 법적 성격을 판단하지 않습니다(리뷰 B4). 서류에 강조할 말풍선은 사용자가 사실 확인 화면에서 고르고, UI 문구도 "상환 약속 발화"처럼 사실을 묘사합니다.
  - SAM 3.1 1단계(감식-1): "chat bubble", "signature", "stamp", "face" 같은 명사구로 마스크를 만듭니다. 판독과 병렬로 돕니다.
  - SAM 3.1 2단계(감식-2): Spark가 준 박스로 말풍선과 글자 개인정보 위치를 보정합니다. 판독이 끝난 뒤 돕니다(리뷰 B2).
  - 영상(P1): 사용자가 고른 말풍선을 프레임마다 추적해 가장 잘 보이는 스틸컷을 뽑습니다. 체크포인트 1 이후에 돕니다.
  - 글자로 된 개인정보(주민번호, 계좌번호)는 Spark 글자 박스에 여백을 더한 사각형으로 가립니다.
- 데모 메시지: "OCR은 글자를 읽고, SAM 3.1은 증거 객체(말풍선, 서명, 도장, 얼굴)를 잘라내고 영상 속에서 따라간다."

#### (6) 결정론적 게이트의 기준값
- 원안은 "AI가 쓴 청구원인"을 "원본 OCR/추출값"과 비교하는데, 추출값도 AI(Spark)가 만든 값이라 기준이 되지 못합니다. 런타임에는 Meta 모델만 호출해야 한다는 규칙(2차 출처) 때문에 Tesseract 같은 별도 OCR을 넣기도 어렵습니다.
- 조치: "사실 확인 화면"을 둡니다. 사용자가 증거 이미지 옆에서 Spark 추출값을 확인·수정하면 그 값이 기준값이 됩니다.
- (v2.2) G1을 두 단계로 나눕니다(리뷰 B1).
  - **G1a 초안 검사**: 문안 작성 담당 출력에 슬롯 밖 리터럴(아라비아 숫자, 한글 수사, 날짜와 상대 날짜, 당사자 이름·호칭)이 있거나 없는 슬롯 이름이 있으면 거부합니다.
  - **G1b 최종 서류 검사**: 편철 후 PDF에서 텍스트를 뽑아 금액, 날짜, 이름이 기준값과 일치하는지 대조합니다. 편철 단계의 버그를 잡습니다.

#### (7) Muse Image 타임라인의 숫자 오류
- 이미지 생성 모델은 그림 속 글자와 숫자를 자주 틀리게 그립니다.
- (v2.2) 조치(리뷰 D3): Muse Image는 **글자 없는 삽화**(인물, 돈, 달력 같은 장면)만 그리고, 날짜와 금액은 코드가 SVG로 위에 얹습니다. G7은 Spark로 그림을 다시 읽어 글자나 숫자가 없는지 확인합니다. 글자가 보이면 1회 재생성하고, 그래도 보이면 SVG만 씁니다.
- 선택(시연용): 그림에 숫자를 그리게 한 뒤 Spark가 다시 읽어 기준값과 비교하는 원래 방식은 "AI가 그린 것을 AI와 규칙이 검증한다" 장면으로만 남겨 둘 수 있습니다.

- 이율 구간:
  - 변제기까지: 약정 이율(이자제한법 상한 연 20%). 약정이 없으면 이자 없음.
  - 변제기 다음 날부터 송달일까지: 지연손해금. 약정 이율이 있으면 그 이율(민법 제397조), 없으면 민법 연 5%(상사채권 연 6%, 상사 여부는 사용자 선택값).
  - 지급명령·소장 송달 다음 날부터: 소송촉진법 연 12%.
- 일부 변제 충당 순서는 비용 → 이자(지연손해금 포함) → 원본입니다(민법 제479조). 미국 트랙에는 별도 규칙을 둡니다(확인 필요).
- 캘리포니아: 계약에 이율이 없으면 위반일 이후 연 10%(Civil Code §3289).
- 계산 규칙(M1에서 고정): 원 미만 버림, 지연손해금은 변제기 다음 날부터 변제일 당일까지 포함, 1년 365일 고정(윤년 처리는 M1에서 근거 확인 후 테스트로 고정), `Decimal` 사용.
- 고정 테스트 예시: 원금 5,000,000원, 변제기 2026-04-10, 이자 약정 없음, 2026-05-01 1,000,000원 변제.

| 단계 | 값 |
|---|---|
| 지연손해금 기간 | 2026-04-11 ~ 2026-05-01, 21일 |
| 지연손해금 | 5,000,000 × 5% × 21/365 = 14,383.56 → 14,383원 |
| 충당 | 지연손해금 14,383원, 원본 985,617원 |
| 남은 원금 | 4,014,383원 |
| 기산일 | 2026-05-02 |
| 청구취지 | "채무자는 채권자에게 4,014,383원 및 이에 대하여 2026. 5. 2.부터 이 사건 지급명령 정본 송달일까지는 연 5%, 그 다음 날부터 다 갚는 날까지는 연 12%의 각 비율로 계산한 돈을 지급하라." |

- 화면의 "예상 총액"은 가정한 기준일을 함께 표시하는 참고값으로만 둡니다.
- 위 규칙의 법적 근거는 법령 원문으로 다시 확인한 뒤 `specs/`에 조문을 적어 둡니다.

#### (9) 개인정보 가림의 근거와 범위
- FRCP Rule 5.2는 연방법원 규칙입니다. 캘리포니아 주법원 소액재판에는 California Rules of Court rule 1.201(SSN과 금융계좌번호는 끝 4자리만)이 적용됩니다.
- 증명 대상인 송금 계좌까지 전부 가리면 송금 증명이 약해집니다. 계좌번호는 끝 4자리를 남기고, 사건과 무관한 제3자 정보만 전부 가립니다.
- 원본은 보존하고 가공은 사본에만 합니다.
- (v2.2) 가림은 **이미지 픽셀을 바꾼 사본**으로 만든 뒤 PDF에 넣습니다. PDF 위에 검은 사각형 주석만 얹으면 아래 정보가 남습니다(리뷰 E1).
- (v2.2) P0 누출 검사(규칙): 최종 PDF에서 이미지를 뽑아 가림 영역 픽셀을 확인하고, PDF 텍스트와 메타데이터에 전체 주민번호·계좌번호가 없는지 정규식으로 검사합니다(리뷰 E2).
- P1 G6: 최종 PDF를 Spark에 그대로 넣어 다시 판독하고, 전체 번호가 보이면 차단합니다.

Muse Code 사용법 (Meta 문서 기준, 2026-11-02 확인):
- 설치(Windows PowerShell): `irm https://dev.meta.ai/install.ps1 | iex` → `muse --version`으로 확인. Windows에서는 명령을 PowerShell로 실행하고, 첫 샌드박스 초기화 때 관리자(UAC) 창이 뜰 수 있습니다.
- 로그인: 처음 실행할 때 브라우저 로그인 또는 API 키. 비대화 실행은 환경 변수 `META_API_KEY`를 씁니다. API 키가 브라우저 로그인보다 우선합니다.
- 모델: 기본값이 `muse-spark-1.2`이므로 `--model muse-spark-1.3` 또는 대화 중 `/models`로 1.3을 고릅니다.
- 지시 파일: 각 폴더에서 `AGENTS.md` → `CLAUDE.md` → `.agents/AGENTS.md` → `.claude/CLAUDE.md` 중 처음 있는 파일을 읽습니다. 작업 폴더를 신뢰(trust)해야 프로젝트 지시 파일이 로드됩니다. 루트 `AGENTS.md`가 Muse Code와 Claude가 함께 쓰는 지시 파일입니다.
- 프로젝트 메모리: `.agents/memory/MEMORY.md`와 주제별 파일(커밋 대상).
- 실행 방식: 대화형 `muse`, 헤드리스 `muse exec "<지시>"`.
- 승인과 샌드박스는 처음부터 켜져 있습니다. 승인 모드는 `--approval-mode`로 정합니다.
- Contributor 모드: 구독은 기본으로 켜져 있습니다. API 키 종량제에서 기본값이 무엇인지는 도움말에 없으므로 설정에서 꺼져 있는지 직접 확인합니다(1-2(10)).
- 요금: 구독(Everyday $5, High $15, Power $50, Maximum $200 /월, Everyday 기준 5시간당 10~50 프롬프트) 또는 API 키 토큰 과금. 구독은 Muse Code 온보딩 때 자동으로 연결되는 Muse Code 전용 키에만 적용되고, 그 밖의 API 키는 토큰 과금입니다("Any additional API keys you create under your Meta Model API account will be billed through pay-as-you-go", Meta 도움말). 이 프로젝트는 구독 없이 API 키 종량제로 씁니다(아래 크레딧 항목).
- 크레딧(v2.2 보충, 11/2 사용자 확인): Muse Code는 과금 방식이 둘입니다.
  - 종량제: API 키를 넣어 쓰면 토큰 단위로 과금되고 $150 크레딧에서 차감됩니다.
  - 월 구독($5~$200): 크레딧으로 낼 수 없고 카드로 정기 결제됩니다.
  - **결정(사용자, 11/2): 구독은 결제하지 않고 API 키 종량제로 씁니다.** 따라서 Muse Code 개발과 앱 실호출이 같은 $150을 나눠 씁니다(배분은 4-7). 크레딧을 다 쓰면 그 뒤 사용분은 카드로 청구되고 Spend Limit은 이를 막지 않습니다.
  - 근거: 대회 FAQ와 사용자가 원문을 확인한 설명. Meta 도움말 구독 페이지 자체에는 크레딧 언급이 없고 "billed per token consumed with your Meta Model API key"만 있습니다.

### 4-3. 작업 방식: 지시 → 구현·검증 → 리뷰

1. **지시서 작성 (Claude)**: `specs/tasks/M<N>-<이름>.md`에 목표, 범위, 하지 않을 일, 참조할 specs 절 번호, 만들거나 바꿀 파일, 완료 기준(테스트 명령과 기대 결과), 리포트 형식을 적습니다. 지시서 하나는 Muse Code가 한 세션에 끝낼 수 있는 크기(대략 1~3시간)로 자릅니다.
2. **전달 (사용자 선택, 미정)**:
   - 가안: 사용자가 Muse Code 대화창(`muse --model muse-spark-1.3`)에서 "specs/tasks/M1-core.md를 읽고 수행해"라고 지시합니다. 진행을 직접 보며 승인할 수 있습니다.
   - 나안: Claude가 `muse exec --model muse-spark-1.3 "<지시서 경로>를 읽고 수행해"`를 헤드리스로 실행하고, 끝나면 바로 리뷰합니다. 사용자 손이 덜 가지만 승인 모드를 미리 정해야 합니다(샌드박스 유지, 작업 폴더 밖 쓰기 금지).
3. **구현·검증 (Muse Code)**: 구현하고 완료 기준 테스트를 실행한 뒤 `reports/M<N>.md`에 변경 파일, 실행한 명령과 결과(통과·실패 수), 실호출 비용, 남은 문제, specs 수정 제안을 적습니다.
4. **리뷰 (Claude)**: 아래 체크리스트로 검사하고 결과를 `reports/M<N>-review.md`에 적습니다. 고칠 것이 있으면 수정 지시서(`specs/tasks/M<N>-fix<k>.md`)로 되돌립니다.
5. **승인과 커밋 (사용자)**: 리뷰를 통과하면 사용자 승인 후 커밋합니다.
   - (v2.3 보충, 11/3 12:05 사용자 결정) 사용자 승인을 묻지 않습니다. 리뷰는 Claude 서브에이전트 여럿이 서로 다른 관점으로 따로 검토하고 서로의 결과를 비판·교차 확인한 뒤 Claude가 통과·수정을 정합니다. 통과하면 Claude가 비밀값 검사 후 커밋하고 중간중간 푸시합니다.

리뷰 체크리스트(모든 마일스톤 공통):
- 완료 기준 테스트를 Claude가 다시 실행해 리포트 결과와 같은지
- 지시서 범위 밖 변경이 없는지, `specs/`와 어긋나는 구현이 없는지
- 금지 명칭(허용 목록 밖), 비밀값, 실제 개인정보가 코드·fixture·리포트에 없는지
- `-contributor` 모델 ID를 쓰지 않는지
- 실호출이 있었다면 비용이 기록되고 예산 상한 안인지
- 남은 크레딧(사용자가 대시보드에서 확인한 값)과 이번 마일스톤의 Muse Code 사용액, 멈춤 기준 $50과의 거리(4-7)
- PDF·화면은 렌더 이미지로 직접 확인

### 4-6. 테스트 전략

| 레벨 | 내용 | 실행 | Meta 호출 |
|---|---|---|---|
| L1 단위 | 계산기, 게이트, 스키마, 해시, 스탬프, 가림 픽셀, PDF 필드 | Muse Code 작성·실행, Claude 재실행 | 없음 |

CI는 선택입니다. 둔다면 오프라인 L1·L2만 돌립니다.

L1 주요 케이스:
- 계산기 KR: 1-2(8) 표의 값(지연손해금 14,383원, 남은 원금 4,014,383원, 기산일 2026-05-02, 청구취지 문구)이 정확히 일치. 이자 약정이 있는 경우, 상사채권(연 6%), 이자제한법 상한 초과 약정 입력 케이스 추가.
- 계산기 CA: $5,000, 위반일부터 연 10% 단리, 센트 단위까지 일치.
- G1a: 변조 100건 자동 주입. 아라비아 숫자, 한글 수사("오백만 원", "5백만원"), 날짜와 상대 날짜("4월 10일", "다음 달", "열흘 뒤"), 당사자 이름·성·호칭("김 씨", 이름만), 없는 슬롯 이름. 100% 차단, 정상 초안은 통과.
- G1b: 편철된 PDF 텍스트의 금액(4,014,383 → 4,014,388), 날짜, 이름을 바꾼 변조 주입 100% 차단, 정상 서류 통과.
- G2: 이체 증빙 또는 변제기 근거가 없으면 보류(HOLD)와 빈 양식 칸 목록 반환. 문구에 법적 판단 표현 없음.
- G3: 근거 태그가 없는 사실 문장, 존재하지 않는 호증 번호는 거부. `[[USER]]` 진술 문장은 허용. 정형 문구는 문안 작성 담당 출력에 있으면 거부.
- 슬롯: 문안 원문에 슬롯 밖 리터럴이 있으면 거부, 치환 후 남은 슬롯 0개, 인용 슬롯이 사용자 확인 원문으로 바뀜.
- 코디네이터: 가짜 에이전트로 정상, HOLD(G2, G4), 스키마 재시도, 수정 루프 초과, 예산 초과 경로가 기대 상태로 끝남.
- 명칭: UI 문자열, 프롬프트, 생성 서류에서 금지 명칭이 허용 목록 밖 0건. 허용 목록 문구(고지)는 통과.
- G4: 30,000,001원은 소액사건 불가 안내, $12,501은 미국 트랙 차단. (11/3 보충) 한국은 보류하지 않고 안내 문구만 남기며, 비교 기준은 청구 원금입니다(에이전트 설계 4-3 보충).
- 해시: 1바이트 변경 검출, 원본과 가공 사본의 해시 분리 기록.
- 가림: 가린 영역 픽셀이 모두 검정, 박스 여백 적용, 원본 파일 불변, 계좌번호 끝 4자리 유지. 최종 PDF에서 이미지를 뽑아 가림 영역 확인, PDF 텍스트와 메타데이터에 전체 주민번호·계좌번호 0건.
- PDF: 한글 폰트 임베딩, 텍스트 추출 결과가 기준값과 일치, 호증 순서와 쪽수, (P1) SC-100 필드를 다시 열었을 때 값 일치.

L3 판정 기준:

- PDF 라이브러리: PyMuPDF는 픽셀 가림(`apply_redactions`)과 PDF 이미지 추출 검사에 편해서 그대로 씁니다. PyMuPDF는 AGPL이므로 저장소 라이선스를 AGPL-3.0으로 둡니다(Claude 결정, 사용자 확인 필요). MIT 등을 원하면 pypdf + ReportLab(NanumGothic TTF)로 바꿉니다(리뷰 E4).
- (v2.3, 11/3) 위 항목은 대체되었습니다. 기존 저장소 스택(pypdf, reportlab, Pillow)을 쓰고 PyMuPDF는 쓰지 않으며, 코드 라이선스는 **MIT**입니다(Claude 결정, 사용자가 판단을 위임). 글꼴은 OFL 1.1, SC-100 양식은 California Judicial Council 양식으로 MIT 대상이 아닙니다. 디렉터리는 현재 저장소 구조(`backend/app/services/`, `backend/app/meta/`, `frontend/` 바닐라 JS)를 따릅니다.
- 프런트엔드 빌드 도구(Vite)는 Claude 결정입니다.

### 4-10. 백엔드 API

| 메서드 | 경로 | 내용 |
|---|---|---|
| POST | `/api/cases` | 사건 생성 |
| POST | `/api/cases/{id}/evidence` | 증거 업로드(접수 담당: 해시, 호증 번호) |
| POST | `/api/cases/{id}/run` | 코디네이터 실행(다음 체크포인트 또는 HOLD까지) |
| GET | `/api/cases/{id}/agents` | 에이전트 보드 상태와 감사 로그 |
| GET | `/api/cases/{id}/review` | 체크포인트 1 화면 데이터(사실 후보, 충돌, 질문, 발화 유형, 가림 계획) |
| PUT | `/api/cases/{id}/facts` | 사실값 확정, 강조 발화 선택, 채무자 주소·제출 법원, 가림 확인(기준값 저장) |
| GET | `/api/cases/{id}/drafts` | 게이트를 통과한 초안 문장 목록 |
| PUT | `/api/cases/{id}/drafts` | 문장별 수정·승인 (v2.2 신규, 수정 문장은 G1a·G3를 다시 통과해야 함) |
| GET | `/api/cases/{id}/package?jurisdiction=kr\|us` | 체크포인트 2 서류 패키지 |
| DELETE | `/api/cases/{id}` | 사건과 업로드 파일 삭제 |

환경 변수 `META_MODE=live|record|replay`로 실호출, 응답 저장, 재생을 전환합니다.

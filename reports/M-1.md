## 5. 미해결 문제와 지시서·specs와의 차이

지시서대로 한 일과 범위 준수를 위해 남긴 것:

- 삭제한 테스트(2번): `test_statute_of_limitations_calculation`,
  `test_verification_blocks_expired_statute_of_limitations`. 소멸시효 계산·차단 기능
  삭제에 따른 것으로, 리포트에 이름을 적는다.
- 1b 테스트 처리 이유: 지시서가 고치라고 한 `test_verification_tampering_reconciliation`은
  실제 코드에서 손대지 않기로 한 LLM 청구금액 비교(`:362-368`) 경로만 건드린다(이체증
  추출액과 원금은 픽스처에서 서로 같다). 그래서 이 테스트는 수정 없이 유지했고 그대로
  통과한다. 새 보류 동작은 `test_transfer_amount_mismatch_requires_human_check` 추가로
  검증한다.
- 1b 문구 범위: "강제 정렬"은 이체증 비교 메시지에서 삭제했다. LLM 경로(`:362-368`)의
  "복원" 문구와 그 경로가 쓰는 `RECONCILED` 설명·라우터 docstring은 "이번에 손대지
  않는다"는 지시를 지켜 그대로 두었다.
- 1a 범위 준수: 이름·번호·주소·우편번호 교체는 지시서의 4개 파일에만 적용했다.
  `sample_evidence/` 텍스트와 화면 캔버스·샘플 생성 스크립트 속 표시 이름은 손대지
  않았다. 미국 샘플 채무자(허구 인물·가상 주소·555 번호)는 이미 가상이어서 유지했다.
- 브랜드 범위 준수: 마스킹 표시 속 `국민은행` 1건(화면 캔버스 수신 계좌행)은 F13 목록에
  없어 남겼다. 기존 증거 제목 `Promissory Admission`(라우터·화면 프리셋·테스트)은
  지시서에 없어 브랜드 부분(`iMessage`→`SampleTalk`)만 고치고 제목은 유지했다.
- 과장 표현: 화면의 `0% Hallucination Proof`는 지시서의 `Zero-hallucination guarantee`와
  같은 부류라서 `Verified values only`로 바꿨다. 테스트 수 표시(`25/25`, `All 25`)는
  최종 25개와 일치하므로 유지했다.
- 줄바꿈: 편집 대상 텍스트 파일의 CRLF를 LF로 정규화했다(내용 변경 없음. `git diff`에
  내용 변경만 표시됨을 `numstat`으로 확인). `sample_evidence/*.txt`는 `-text`+LF로
  유지하고, 재생성 스크립트에 `newline="\n"`을 넣어 Windows에서도 LF로 나오게 했다.
- 기존 문제(이번 범위 밖): `uvicorn`이 `requirements.txt`에 없어 README의 서버 실행
  명령은 별도 설치를 가정한다. 계산기(F4~F6)는 지시대로 손대지 않았다(M1).
- 비밀값 검사: `.env` 추적 검사는 코드 점검으로 확인했다(`.env` 생성·열람 금지 규칙상
  실제 `.env` 파일로는 시험하지 않음).
- 작업 시작 전부터 있던 `specs/multi_agent_architecture.md`의 미커밋 수정은 건드리지
  않았다.
